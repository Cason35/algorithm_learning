# Day 13：递归

## 今天目标

Day 13 学递归。你在 Day 12 的归并排序和快速排序里已经用过递归，今天要把它从“会照着写”变成“能自己设计”。

递归的核心不是函数调用自己，而是：

```text
把一个问题缩小成结构相同的子问题，直到最小问题可以直接回答。
```

今天要掌握 4 件事：

1. 明确递归函数的含义，也就是“这个函数承诺返回什么”。
2. 先写终止条件，保证问题一定会缩小并最终停止。
3. 理解调用栈如何保存每一层尚未完成的计算。
4. 能从递归层数和每层工作量判断时间、空间复杂度。

## 1. 生活例子

想象你在找一个文件夹里共有多少个文件。文件夹里既可能有文件，也可能有子文件夹：

```text
课程资料/
├── README.md
├── JavaScript/
│   ├── array.md
│   └── function.md
└── Algorithm/
    └── recursion.md
```

处理每个文件夹的方法都一样：

1. 普通文件直接计数。
2. 遇到子文件夹，就用同样的方法统计子文件夹。
3. 把结果加起来。

这种“结构相同、规模更小”的问题非常适合递归。

## 2. 递归的三个组成部分

以阶乘为例：

```text
5! = 5 × 4 × 3 × 2 × 1
```

可以把它写成：

```js
function factorial(n) {
  if (n <= 1) {
    return 1;
  }

  return n * factorial(n - 1);
}
```

这里有三个关键部分：

1. 函数定义：`factorial(n)` 返回 `n!`。
2. 终止条件：`n <= 1` 时直接返回 `1`。
3. 规模缩小：把 `factorial(n)` 变成 `n * factorial(n - 1)`。

如果缺少终止条件，或者参数没有向终止条件靠近，就会无限递归，最终出现 `RangeError: Maximum call stack size exceeded`。

## 3. 调用栈怎么工作

计算 `factorial(4)` 时，调用过程是：

```text
factorial(4)
4 × factorial(3)
4 × 3 × factorial(2)
4 × 3 × 2 × factorial(1)
4 × 3 × 2 × 1
```

到达终止条件后，再从最深层逐层返回：

```text
factorial(1) = 1
factorial(2) = 2
factorial(3) = 6
factorial(4) = 24
```

每一层调用都要在调用栈里保存自己的参数和未完成工作。因此，即使递归没有创建数组，也不代表空间复杂度是 `O(1)`。

## 4. 递归求数组和

数组 `[2, 4, 6]` 的和可以拆成：

```text
从下标 0 开始的和
= nums[0] + 从下标 1 开始的和
= nums[0] + nums[1] + 从下标 2 开始的和
```

当下标到达数组末尾时，剩余部分的和是 `0`。

推荐使用下标推进，而不是每层都调用 `slice(1)`：

```js
function recursiveSum(nums) {
  function sumFrom(index) {
    if (index === nums.length) {
      return 0;
    }

    return nums[index] + sumFrom(index + 1);
  }

  return sumFrom(0);
}
```

这样时间复杂度是 `O(n)`，调用栈空间是 `O(n)`，且不会反复复制子数组。

## 5. 快速幂：一次把问题缩小一半

普通计算 `2^10`，可以连续乘 10 次。递归不一定只能每次减 1；利用下面的关系，可以每次把指数减半：

```text
当 n 是偶数：x^n = x^(n/2) × x^(n/2)
当 n 是奇数：x^n = x^floor(n/2) × x^floor(n/2) × x
```

注意不要把同一个递归调用写两次：

```js
// 会重复计算，不推荐
return fastPower(x, n / 2) * fastPower(x, n / 2);
```

应该保存结果再复用：

```js
const half = fastPower(x, Math.floor(n / 2));
```

这样递归深度和时间复杂度都可以达到 `O(log n)`。

## 6. 递归展开嵌套数组

对于嵌套数组：

```js
[1, [2, [3, 4]], 5]
```

从左到右检查每个元素：

- 如果是数字，加入结果。
- 如果是数组，递归处理这个数组。

最终得到：

```js
[1, 2, 3, 4, 5]
```

这类题的递归深度由最大嵌套层数决定。设所有数字和数组元素总数为 `n`、最大嵌套深度为 `d`，时间复杂度是 `O(n)`，不计返回结果时的调用栈空间是 `O(d)`。

## 7. 如何判断能不能用递归

看到问题时可以问自己：

1. 当前问题能否拆成一个或多个结构相同的更小问题？
2. 最小的问题是什么，能否直接返回答案？
3. 每次调用是否真的更接近终止条件？
4. 每层做多少工作，总共有多少层？
5. 输入很大时，调用栈会不会过深？

递归通常写起来更贴近问题定义，但循环往往更节省栈空间。选择哪一种，要看问题结构和输入规模，而不是看到递归题就强行递归。
