# Specs 变更记录规范

`specs/` 保存可随 Git 提交的设计与变更记录，用于解释训练路线、仓库规则、目录结构、测试机制、自动化或批量课程内容为什么改变，以及如何验证和回滚。

## 何时创建

- 修改 `AGENTS.md`、路线、任务生成或学习状态规则。
- 调整 Day 目录结构、测试方式、公共算法工具或自动化。
- 批量新增、重排或迁移课程与作业。

日常完成一个 `work.js`、单次批改和学习进度使用原有 Day 文件、`PROGRESS.md` 与 `learning-state.yml`，不重复创建 spec。

## 命名与维护

- 文件名：`YYYY-MM-DD-<topic>.md`，topic 使用英文 kebab-case。
- 同一任务持续更新同一文件，不为每轮对话重复创建。
- 从 `_template.md` 复制；开始时写计划，完成后补实际结果。
- Spec 与对应修改一起提交，不得记录秘密或个人敏感信息。
