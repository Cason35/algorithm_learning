## 1. 第二周工具箱

### 栈

典型信号：

```text
最近加入的先处理、嵌套结构、表达式计算、撤销、匹配
```

栈里通常保存“已经看到、但还没有完成处理”的内容。入栈和出栈应当都是 `O(1)`。

### 队列与双端队列

典型信号：

```text
按到达顺序处理、固定窗口、窗口最值、过期元素、候选下标
```

普通队列只关心先来后到；单调双端队列还会主动删除不可能成为答案的候选值。

### 链表

典型信号：

```text
节点、next、原地反转、中点、倒数位置、不能随机访问
```

链表题要特别注意保存即将断开的 `next`，以及修改结构后是否需要恢复。

### 二分查找

典型信号：

```text
有序、单调、第一次、最后一次、最小可行值、最大可行值
```

找边界时，即使遇到目标也不能立即返回，而要继续向目标边界收缩。

## 2. 任务一：逆波兰表达式求值

逆波兰表达式把运算符写在两个操作数后面：

```text
普通表达式：(2 + 1) * 3
逆波兰表达式：2 1 + 3 *
```

从左到右扫描 token：

- 数字入栈。
- 遇到运算符，弹出两个数字计算，再把结果压回栈。

减法和除法要注意顺序。先弹出的是右操作数，后弹出的是左操作数：

```text
left operator right
```

除法结果向零截断，可以使用 `Math.trunc`。

## 3. 任务二：每个窗口的第一个负数

给定：

```js
nums = [12, -1, -7, 8, -15, 30, 16, 28]
k = 3
```

每个长度为 3 的窗口中，第一个负数依次是：

```js
[-1, -1, -7, -15, -15, 0]
```

如果每个窗口都从头扫描，会花费 `O(nk)`。更好的方法是用队列保存“当前及未来窗口里仍然有效的负数下标”：

1. 右端加入新出现的负数下标。
2. 左端删除已经离开窗口的下标。
3. 队首就是当前窗口的第一个负数；队列为空则记录 `0`。

每个下标最多入队、出队各一次，因此时间是 `O(n)`。

在 JavaScript 中不要反复使用数组的 `shift()` 模拟出队，因为它会移动剩余元素。可以保留一个 `head` 下标指向当前队首，让出队保持 `O(1)`。

## 4. 任务三：判断回文链表

判断链表是否回文，最直观的做法是把节点值复制到数组中，但这需要 `O(n)` 额外空间。

本题要求组合 Day 10 的两个技能：

1. 用快慢指针找到前半部分的末尾。
2. 原地反转后半部分。
3. 从链表头和反转后的后半部分同时比较。
4. 再次反转后半部分并接回去，恢复输入链表。

恢复链表很重要：一个函数即使返回值正确，如果没有得到授权却永久改变了输入结构，仍然会给调用者留下副作用。

特殊情况：空链表和单节点链表都是回文。

## 5. 任务四：查找目标值范围

在升序数组中查找目标值的第一次和最后一次出现位置：

```js
nums = [5, 7, 7, 8, 8, 10]
target = 8
// [3, 4]
```

目标不存在时返回：

```js
[-1, -1]
```

不能找到一个目标后向两边线性扫描，因为重复元素很多时会退化为 `O(n)`。应当进行两次边界二分：

- 第一次找最左侧目标。
- 第二次找最右侧目标。

两个二分各花费 `O(log n)`，总复杂度仍然是 `O(log n)`。

### 需要二次修改的点

队首下标能解决 `shift()` 的时间问题，但不会自动释放数组前面的存储。若要同时满足时间 `O(n)`、空间 `O(k)`，可以选择：

- 使用固定长度的循环队列；或
- 使用 `Map` 保存队列位置，并在元素过期时 `delete`。

例如队列只保存有效项时，核心状态可以是：

```js
const queue = new Map();
let head = 0;
let tail = 0;

// 入队：queue.set(tail, index); tail += 1;
// 出队：queue.delete(head); head += 1;
// 队首：queue.get(head)
```

这样逻辑位置可以持续增长，但 `Map` 中实际保存的下标始终不超过窗口大小。

代码中的注释非常认真，但目前几乎每一行都在复述代码动作。实际项目中可以保留“为什么这样做”“变量代表什么”“容易出错的边界”等注释，省略 `left = left.next` 这类代码本身已经表达清楚的内容，让核心思路更突出。
